# React Vite TypeScript 開発手順

## 目的

Windows PowerShell環境で、React + Vite + TypeScriptプロジェクトを安全に導入、実行、検証するための方針を定義する。

この文書は導入方針を示すものであり、現時点ではNode.js、npm、Vite、Reactは導入しない。

## 前提環境

- OS: Windows 10 Home
- Shell: Windows PowerShell 5.1
- 作業ディレクトリ: `C:\Projects\dbd-tournament-site`
- パッケージマネージャー: npm
- Docker: 使用しない

## 使用ツール

採用済み:

- React
- Vite
- TypeScript
- npm

初期導入しない:

- React Router
- UIライブラリ
- Docker
- テストライブラリ
- CSSプリプロセッサ

## Node.jsバージョン方針

- 採用するNode.jsのメジャーバージョンは未決とする。
- Viteの採用バージョンが要求するNode.js範囲を、導入前に公式文書で確認する。
- 長期サポート対象のバージョンを優先する。
- 管理者権限を常用しない。
- 導入方法とインストール先をユーザ承認後に確定する。

## npm運用方針

- パッケージ管理にはnpmを使用する。
- `package-lock.json`を使用し、依存解決結果を固定する。
- グローバルnpmパッケージを前提にしない。
- 依存追加・更新コマンドは実行前にユーザ承認を得る。
- `npm audit fix`を自動実行しない。
- React Router、UIライブラリ、テストライブラリは初期依存へ含めない。

## 初回セットアップ

初回セットアップは別フェーズで行う。
実行前に以下を確定する。

1. Node.jsのバージョン
2. Node.jsの導入方法
3. Viteの採用バージョン
4. ルートへ構築する具体的な方法
5. 既存`index.html`の保持方法
6. 初期ルーティング方式

既存HTML/CSSを上書きする可能性がある生成コマンドは、影響範囲を確認せず実行しない。

## PowerShellコマンド

実際のコマンド列は、Node.jsとViteのバージョン決定後に追記する。
Linux系コマンドを前提にしない。

コマンドを記載する際は、次の操作を分ける。

- バージョン確認
- 初期構成作成
- 依存インストール
- 開発サーバー
- TypeScript検証
- ビルド
- ローカルプレビュー

## 開発サーバー

- ユーザ承認後に定義されたnpm scriptを使用する。
- 外部ネットワークへ公開するホスト設定を初期状態で使用しない。
- 終了時にプロセスが残っていないことを確認する。

## TypeScript検証

- TypeScriptエラーを残したまま移行完了としない。
- `any`による一括回避を行わない。
- 公開データの状態、公開可否、任意値を型で区別する。
- 型検証コマンドは`package.json`確定後に文書へ追記する。

## ビルド

- Viteの本番ビルドが成功することを確認する。
- GitHub Pages用の`base`設定を確認する。
- 出力先の`dist`を生成物として扱う。
- `dist`のリポジトリ管理方針はGitHub Pages公開方式と合わせて決定する。

## ローカルプレビュー

- 本番ビルド後の成果物でページ、リンク、アセットを確認する。
- 開発サーバーだけで検証を完了しない。
- GitHub Pagesのサブパスを想定した確認方法を公開手順に記録する。

## 依存追加ルール

新規依存を追加する場合は、実行前に以下を提示する。

- パッケージ名
- 導入目的
- 追加しない場合の代替案
- 本番依存か開発依存か
- バンドルサイズや運用への影響
- ライセンスと保守状況

## package-lock.jsonの扱い

- `package.json`と同時に整合性を確認する。
- 手作業で内容を書き換えない。
- 意図しない大規模更新が発生した場合は作業を停止する。
- ロックファイルの更新理由を変更報告へ含める。

## commit・push前確認

- React環境導入は、他のドキュメント整備やページ移植と分けた意味ある作業単位として扱う。
- commitまたはpushを提案する前に、`git status`と`git diff`相当で変更対象と差分を確認する。
- `package.json`と`package-lock.json`を作成または更新したフェーズでは、両者の整合性と意図しない依存変更がないことを確認する。
- Codexは変更要約、影響範囲、実行した検証、未決事項、commit message案を提示する。
- `git add`、`git commit`、`git push`はユーザの明示承認後にのみ実行する。
- force pushは禁止する。reset hard、git clean、rebaseなどは、禁止または個別の明示承認必須とする。
- GitHubレビューでReact環境や依存関係について指摘を受けた場合は、`docs/issues`または該当する開発文書へ反映する。

## 禁止事項

- 承認なしのNode.js/npm導入
- 承認なしの依存追加・更新
- グローバルパッケージ前提
- `npm audit fix`の自動適用
- 旧HTML/CSSの削除、改名、移動
- `_cdxuser-*`の削除、移動
- Docker導入
- Git操作

## トラブル対応

- インストールやビルドが失敗した場合、エラーを記録して原因を調査する。
- 依存関係を一括更新して解決しない。
- キャッシュや生成物の削除が必要な場合は、対象、影響、復旧方法を示してユーザ承認を得る。
- PowerShellの実行ポリシーや権限変更で回避しない。

## 導入前チェック

- 必須ドキュメントを確認済みである。
- Node.jsバージョンが決定済みである。
- Vite構築方法が決定済みである。
- 旧HTML/CSSの保持方法が決定済みである。
- 初期ルーティング方式が決定済みである。
- GitHub Pagesのリポジトリ名と公開URLが確認済みである。
- 実行予定コマンドがユーザに承認されている。
