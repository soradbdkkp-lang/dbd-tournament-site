# フロントエンド構成

## 目的

React + Vite + TypeScriptへの段階的な移行方針と、初期実装の責務境界を定義する。

## 採用技術

- React
- Vite
- TypeScript
- npm
- CSS

各ツールの具体的なバージョンは、環境導入フェーズの開始前に決定する。

## 初期導入しない技術

- React Router
- UIライブラリ
- Docker
- 外部データベース
- 外部API
- テストライブラリ
- Markdown変換ライブラリ

追加が必要になった場合は、目的、代替案、影響範囲を提示してユーザ承認を得る。

## 現行構成

現行サイトは以下の静的ファイルで構成される。

| ファイル | 役割 |
|---|---|
| `index.html` | トップページ |
| `rules.html` | 大会ルールの仮ページ |
| `about.html` | 0バイトのプレースホルダ |
| `style.css` | 現行ページの共通スタイル |

これらはReact移行完了まで比較・復旧用に保持し、削除、改名、移動、上書きを行わない。

## 移行後のディレクトリ構成

```text
src/
├─ main.tsx
├─ App.tsx
├─ pages/
│  ├─ HomePage.tsx
│  ├─ RulesPage.tsx
│  └─ NotFoundPage.tsx
├─ components/
│  ├─ layout/
│  ├─ common/
│  └─ rules/
├─ data/
├─ types/
├─ constants/
└─ styles/
```

初期フェーズでは必要なファイルだけを作成し、将来用途だけの空ファイルや空ディレクトリを一括作成しない。

## アプリケーション起動点

- `index.html`はViteのエントリHTMLとして使用する予定とする。
- `src/main.tsx`はReactアプリケーションをDOMへマウントする。
- `src/App.tsx`はページ選択と共通レイアウトの入口を担当する。

既存の`index.html`をVite用に変更する作業は、旧HTMLの保持方法を確定してから行う。

## ページ構成

初期実装は以下の3ページに限定する。

| ページ | 役割 |
|---|---|
| `HomePage` | 開催状況、大会概要、お知らせ、主要導線 |
| `RulesPage` | 承認済みの大会ルールと状態表示 |
| `NotFoundPage` | 未定義の画面やURLに対する案内 |

`about.html`は当面プレースホルダとして保持し、`AboutPage`は初期実装に含めない。

## コンポーネント責務

- ページは表示セクションの組み立てを担当する。
- 共通レイアウトはヘッダー、ナビゲーション、本文領域、フッターを担当する。
- 状態表示は`StatusBadge`へ集約する。
- ルール文言をコンポーネント内へ直接埋め込まず、承認済み公開データから受け取る。
- コンポーネントは`docs`の内容を推測して補完しない。

## データ参照方針

- 大会ルールの正本は`docs`とする。
- `src/data`は承認済み内容の表示用コピーとする。
- `src/data`の型と同期方針は`public-data-model.md`で定義する。
- 草案をMarkdownから自動変換しない。
- 文書間に矛盾がある場合はデータ化を停止する。

## スタイル管理

- `DESIGN.md`を全体方針の正本とする。
- スマホ1カラムを基本とする。
- 状態を色だけで判別させない。
- 初期実装ではCSS ModulesやCSS-in-JSを導入せず、通常のCSSを使用する予定とする。
- 正式配色とスマホナビ形式は未決事項として扱う。

## ルーティング方針

React Routerは初期導入しない。
初期ルーティング方式は未決であり、次の候補から実装前に選択する。

- URLハッシュを用いた最小ルーティング
- 単一ページ内の状態切り替え
- Viteの複数HTMLエントリ

独自ルーティングを複雑化させないことを優先する。

## GitHub Pages対応

- GitHub Pagesでの公開を前提とする。
- Viteの`base`は実際のリポジトリ名と公開URLに合わせる。
- 直接URLと再読み込み時の404を考慮する。
- GitHub Actionsの設定は別フェーズで行う。
- 公開手順の詳細は`docs/operations/github-pages-release.md`で管理する。

## 旧HTML/CSSの保持方針

- React版の表示と内容を比較できる状態を維持する。
- 移行完了条件を満たすまでは旧ファイルを削除しない。
- 移行完了後も削除ではなく退避を優先し、実行前にユーザ承認を得る。

## 移行完了条件

- 初期3ページが仕様どおり表示される。
- 承認済みルールだけが公開される。
- 状態ラベルと非公開制御が機能する。
- スマホ幅とPC幅で主要情報を確認できる。
- GitHub Pagesの`base`配下でリンクとアセットが解決する。
- 旧ページとの比較で意図しない文言欠落がない。
- 関連ドキュメントと索引が更新されている。
