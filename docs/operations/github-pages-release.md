# GitHub Pages公開手順

## 目的

React + Vite + TypeScriptで生成したサイトをGitHub Pagesへ公開するための設計、検証、復旧方針を定義する。

GitHub Actionsの設定は別フェーズで行う。

## 前提

- Viteによる本番ビルドが成功している。
- 公開対象データが承認済みである。
- `docs`と表示内容の照合が完了している。
- GitHubリポジトリ名と公開URLが確定している。
- 公開方式がユーザ承認済みである。

## 公開URL

次を実装前に確認する。

- GitHubアカウントまたはOrganization名
- リポジトリ名
- ユーザーサイトかプロジェクトサイトか
- カスタムドメインの使用有無

現時点では具体的な公開URLは未決とする。

## Vite base設定

プロジェクトサイトの場合、通常はリポジトリ名を含むサブパスを`base`へ設定する。

概念例:

```ts
base: "/dbd-tournament-site/"
```

ユーザーサイトのルートで公開する場合は設定が異なる。
実際の値はリポジトリ名と公開URLの確定後に設定する。

## URL・ルーティング方式

GitHub Pagesはサーバー側のSPAフォールバックを標準提供しないため、`/rules`などへ直接アクセスすると404になる可能性がある。

初期候補:

- ハッシュを用いたURL
- 単一ページ内の状態切り替え
- 複数HTMLエントリ
- 404フォールバック

React Routerは初期導入しない。
URL形式と`NotFoundPage`の到達方法は、React実装前に決定する。

## アセットパス

- Viteの`base`を考慮する。
- ルート絶対パスを安易に使用しない。
- 画像、CSS、JavaScriptがサブパス配下で読み込めることを確認する。
- ファイル名の大文字・小文字を一致させる。
- ローカル開発だけでなく本番ビルド成果物で確認する。

## ビルド成果物

- Viteの出力先は`dist`を想定する。
- `dist`は生成物として扱う。
- `dist`をリポジトリ管理するかは公開方式と合わせて決定する。
- 生成物を手作業で修正しない。
- 元のTypeScript、CSS、公開データを修正して再ビルドする。

## 手動公開フェーズ

GitHub Actions導入前に手動公開を行うかは未決とする。
手動公開する場合も、Git操作とGitHub設定変更はユーザ承認後に行う。

公開手順を確定する際は以下を明記する。

1. ビルド方法
2. 公開対象
3. 公開先
4. 必要な権限
5. 公開確認
6. 失敗時の復旧方法

## GitHubレビュー用push運用

- 1つの意味ある作業単位が完了した時点をpush候補とする。
- push単位は、ドキュメント整備、React環境導入、ページ移植、データ化などのフェーズ単位とする。
- commitまたはpush前に`git status`と`git diff`相当を確認し、意図しないファイルや変更が含まれていないことを確認する。
- Codexは変更要約、影響範囲、検証結果、未決事項、commit message案をユーザへ提示する。
- `git add`、`git commit`、`git push`はユーザの明示承認後にのみ実行する。
- 定期レビューを理由にCodexが無断でpushしてはならない。
- force pushは禁止する。
- `git reset --hard`、`git clean`、rebaseなど、履歴または未保存変更へ影響する操作は禁止または個別の明示承認必須とする。
- GitHubレビューで指摘された内容は、`docs/issues`または該当するdocsへ反映してから次のpush候補へ含める。

## GitHub Actions移行予定

- Actions設定は別フェーズとする。
- ワークフローの権限を最小限にする。
- 使用するActionの提供元とバージョン固定方針を確認する。
- Node.jsバージョンをローカル開発環境と合わせる。
- ビルド失敗時に公開を更新しない構成とする。

## 404への対応

確認項目:

- トップページ以外を直接開けるか
- ブラウザ再読み込みで404にならないか
- 不正なURLから`NotFoundPage`へ到達できるか
- Pages側の404ページとReact側の`NotFoundPage`の役割が重複しないか

対応方式はルーティング方式の決定後に確定する。

## 公開前検証

- HomePageが表示される。
- RulesPageが表示される。
- NotFoundPageまたはPagesの404が意図どおり動作する。
- CSSとJavaScriptが読み込まれる。
- 画像を使用する場合は画像が読み込まれる。
- HomeとRules間のリンクが動作する。
- 外部リンクが正しい。
- 非公開データが含まれていない。
- スマホ幅とPC幅で閲覧できる。
- ページタイトルと言語設定が正しい。
- 旧HTML/CSSが保持されている。

## ロールバック

- 直前の正常な公開物またはコミットを特定できるようにする。
- force pushや履歴改変を復旧手段にしない。
- 公開障害時は新規公開を停止し、原因と影響範囲を確認する。
- 具体的な復旧操作はGit運用と公開方式の承認後に追記する。

## カスタムドメイン

カスタムドメインの使用は未決とする。
使用する場合は、DNS、HTTPS、`CNAME`、Viteの`base`への影響を別途確認する。
