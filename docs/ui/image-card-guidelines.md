# 画像カード表示ガイドライン

## 目的

キラー、MAP、アドオンなどの画像付き選択肢を、ページをまたいで一貫したカードUIとして表示するための共通仕様を定義する。
対象は構成提出ページ、アンケートページ、制限ルール表示ページ、今後のサバイバー用ページ、および同種の画像一覧である。

この文書は画像カードの表示仕様の正本とする。
今後Codexが対象画像をページへ組み込む際は、本書を参照して共通仕様を適用する。
ただし、未決事項、公開データ、ルール内容、個別ページ固有の動作は推測せず、関連docsとユーザ承認を確認する。

## 参照方針

- サイト全体の原則、スマホ優先、アクセシビリティは`DESIGN.md`を優先する。
- フォント、余白、雰囲気、質感は`docs/DESIGN-claude.md`を参考にする。
- 配色、フォーカス色、警告色、エラー色などの状態色は`docs/DESIGN-cohere.md`を参考にする。
- getdesign由来の具体指示が追加された場合は`docs/ui/getdesign-implementation-instructions.md`の対象画面と適用範囲を確認する。
- 参考資料間または既存docsと矛盾する場合は、値を混合して実装せずユーザへ確認する。

## 共通利用範囲

本仕様は以下で共通利用する。

- キラー構成提出ページ
- アンケートページ
- キラー制限、MAP制限、アドオン制限の表示ページ
- 今後追加するサバイバー用ページ
- その他、キラー、MAP、アドオンなどの画像を表示するページ

## 共通画像カード

### 基本構造

- キラー、MAP、アドオン画像は共通カードUIで表示する。
- カードは「画像表示領域」「日本語名」「状態表示」を1つのまとまりとして扱う。
- 画像の下には必ず日本語名を表示し、画像と日本語名のどちらも省略しない。
- 日本語名は画像ファイル名ではなく、承認済みデータの`name`または同等の日本語表示名を使う。
- 画像ファイル名とIDは英数字を基本とし、参加者向け表示名とは分離して管理する。
- 画像の縦横比や余白が異なっても、カード全体の余白、名前表示、状態表示の位置が崩れない構造にする。
- 一覧内では画像表示領域と名前表示領域の基準を揃え、画像の元サイズだけでカード寸法を決めない。
- 画像読み込みに失敗した場合も、日本語名と状態が確認できるようにする。

### 操作とアクセシビリティ

- 選択可能なカードは、カード全体をクリックまたはタップ対象とする想定とする。
- キーボード操作時のフォーカス位置を視覚的に示す。
- 選択状態や使用可否を色だけで伝えず、チェックマーク、枠線、ラベル、文言を併用する。
- 画像の代替テキストは日本語表示名を基準とし、周囲に同じ名前がある場合は重複読み上げを避ける実装を検討する。
- 状態ラベルが画像を過度に覆わず、画像と日本語名の双方を確認できるようにする。

## キラー画像

- キラー画像の下に日本語名を表示する。
- キラー名はデータ上の`name`または同等の日本語表示名を使う。
- 選択中は枠線、チェックマーク、背景変化などを併用して明確にする。
- 制限ルール表示ページでは、選択操作がない場合もカード構造と日本語名表示を共通化する。

## MAP画像

- MAP画像の下に日本語名を表示する。
- MAP名はデータ上の`name`または同等の日本語表示名を使う。
- 構成提出では、キラー選択後に使用可能なMAPだけを選択可能にする想定とする。
- 使用不可または対象外のMAPを一覧に残す場合は、選択不可の文言と見た目を併用する。
- 使用禁止と単なる対象外を同じ意味として扱わず、データ上の理由に対応した文言を表示する。

## アドオン画像

### 基本構造

- アドオン画像は背景透過素材を前提とする。
- 画像表示領域と同じ大きさのレアリティ背景を敷き、その上に透過アドオン画像を重ねる。
- レアリティ背景、アドオン画像、日本語名、状態表示を1つのカードとして扱う。
- アドオン画像の下に、承認済みデータの日本語名を表示する。
- 画像配置パスは`public/images/addons/<killerId>/<addonId>.<ext>`を前提とする。
- 公開時の参照パスはViteおよびGitHub Pagesの`base`を考慮して解決する。
- アドオンは最大2個まで選択する想定とする。
- アドオンを選択せずに提出することは可能とするが、構成提出時に未選択であることを確認する文言を表示する想定とする。
- 1個だけ選択した場合の確認要否と文言は、構成提出ページの機能仕様で決定する。

### レアリティ定義

アドオンの`rarity`内部IDは以下の5種類だけを使用する。

| 表示名 | 内部ID |
|---|---|
| common | `common` |
| uncommon | `uncommon` |
| rare | `rare` |
| very rare | `very_rare` |
| visceral | `visceral` |

- 画面表示では`very_rare`ではなく`very rare`と表示する。
- `veryRare`、`ultraRare`、`event`は今回のレアリティ分類に含めない。

#### 外部資料の `Ultra Rare` の扱い

- 外部資料上で `Ultra Rare` と表記されているアドオンは、本プロジェクトでは `visceral` 候補として扱う。
- これはゲーム公式表記の転記ではなく、この大会サイト内のレビュー用分類ルールである。
- `Ultra Rare` から `visceral` への変換は正式確定ではなく、`reviewStatus: "pending"` の間はユーザ確認待ちとして扱う。
- 正式確定は、ユーザ確認後に `finalRarity` または正式データへ反映する。
- 上記以外の値を推測で5種類のいずれかへ変換しない。
- docsと承認済み表示用データが矛盾する場合は、表示実装を停止してユーザへ確認する。

実装時のデータは、以下の考え方を基準とする。

```ts
{
  id: "sample_addon",
  name: "アドオン名",
  killerId: "sample_killer",
  rarity: "very_rare",
  rarityLabel: "very rare",
  point: 3,
  isBanned: false,
  imagePath: "/images/addons/sample_killer/sample_addon.webp"
}
```

### レアリティ背景

- レアリティは、画像表示領域全体の背景色で区別する。
- 背景色の上でも透過画像の輪郭が判別できるコントラストを確保する。
- レアリティを背景色だけで判別させず、必要な画面では`rarityLabel`を文字でも表示する。
- 選択中、使用禁止、選択不可の状態表示がレアリティ背景に埋もれないよう、状態用の枠線、ラベル、アイコンを別レイヤーで表示する。
- DBDのレアリティ色を参考にできるが、サイトの状態色と誤認しない明度・コントラストに調整する。

レアリティ背景色の具体的な色値は未決定である。
実装前に実画像を重ねた状態で、以下の方向性を候補として比較し、ユーザ承認を得る。

| 内部ID | 色の方向性候補 | 状態 |
|---|---|---|
| `common` | 茶系または低彩度の中間色 | 未決定 |
| `uncommon` | 緑系 | 未決定 |
| `rare` | 青系 | 未決定 |
| `very_rare` | 紫系 | 未決定 |
| `visceral` | 赤系または深紅系 | 未決定 |

## 状態表示

### 表示優先順位

複数状態が重なる場合は、参加者への影響が大きい状態を優先する。

1. 使用禁止
2. ポイント超過などによる選択不可
3. 選択中
4. 通常状態

使用禁止とポイント超過が同時に成立する場合は「使用禁止」を表示理由として優先する。
状態の理由をデータから判断できない場合は、見た目だけで理由を推測しない。

### 通常状態

- 画像、背景、日本語名を通常表示する。
- 選択画面では、選択可能であることが分かる見た目と操作対象を用意する。
- 制限表示など選択を伴わない画面では、選択可能に見える操作表現を付けない。

### 選択中

- 枠線、チェックマーク、背景変化など、少なくとも2つの手掛かりを併用する。
- レアリティ背景色を選択色で上書きせず、アドオンのレアリティを確認できるようにする。
- スマホでもチェックや枠線が画像外へ切れず、日本語名と同時に確認できるようにする。
- キーボードフォーカスと選択中は別の状態として見分けられるようにする。

### ポイント超過による選択不可

- 灰色表示または不透明度の低下に加え、「選択不可」などの文言を表示する。
- クリックまたはタップしても選択できない状態にする想定とする。
- 1つ目のアドオン選択後、残りポイントを超えるアドオンを選択不可にする想定とする。
- 不透明度を下げる場合も、日本語名と選択不可の理由を読めるコントラストを維持する。
- 選択不可の理由を補足できる画面では、「残りポイントを超過」など具体的な文言を表示する。

### 使用禁止

- 使用禁止の項目は、ルール確認のため一覧へ表示してよい。
- 「使用禁止」と文字で明記し、選択不可にする。
- 警告色、禁止アイコン、枠線などを併用し、色だけに依存しない。
- ポイント超過による選択不可より使用禁止表示を優先する。
- レアリティ背景は維持してよいが、使用禁止ラベルの判読性を優先する。

### その他の選択不可

- MAPの対象外、選択上限到達、前提となるキラー未選択など、ポイント超過以外の理由でも選択不可表示を共通利用できる。
- 可能な限り「選択不可」だけで終わらせず、理由を短い文言で示す。
- 使用禁止ではない項目に「使用禁止」の警告表現を流用しない。

## スマホ表示

- スマホでカードを過度に縮小せず、列数を減らして画像と日本語名の可読性を保つ。
- 日本語名が長い場合も、極端な文字縮小や画像領域への重ね表示で解決しない。
- カード全体をタップしやすい領域とし、隣接カードの誤操作を避ける間隔を確保する。
- 選択中、選択不可、使用禁止のラベルやアイコンが画像外へ切れないようにする。
- 横スクロールを必須にする一覧は避け、グリッドの列数を段階的に減らす。
- 画像の元サイズが小さい場合も、拡大による過度なぼけとレイアウト崩れの両方を確認する。
- 固定のカード幅、列数、画像領域サイズ、ブレークポイントは実画像を使った画面検証後に決定する。

## データ管理

- 画像カードの表示仕様と公開ルールの正本はdocsとする。
- `src/data`はユーザが承認した表示用コピーだけを保持する。
- 画像ファイル名とIDは英数字、参加者向け表示名は日本語データで管理する。
- ファイル名から日本語名、レアリティ、使用可否、ポイントを推測して公開しない。
- 非公開データを公開画面へ表示しない。
- 画像カードは見た目だけでルール、状態、公開可否を決定せず、承認済みデータを受け取って表示する。

## 実装時の確認

1. 対象データがdocsで承認済みか
2. 画像と日本語名が常にセットで表示されるか
3. アドオンの`rarity`が定義済みの5種類だけか
4. `very_rare`が画面上で`very rare`と表示されるか
5. レアリティ背景上で画像を判別できるか
6. 選択状態とフォーカス状態を見分けられるか
7. 使用禁止と選択不可の理由が文字でも分かるか
8. 使用禁止がポイント超過表示より優先されるか
9. スマホとPCの双方で画像、日本語名、状態表示が欠けないか
10. GitHub Pagesの`base`配下で画像パスが解決するか

## 未決事項

- 5種類のレアリティ背景色の正式な色値
- レアリティラベルを常時表示する画面と、詳細表示に限定する画面
- カード、画像表示領域、グリッドの具体的な寸法
- 1個だけアドオンを選択した場合の提出確認文言
- 画像読み込み失敗時に使用する共通プレースホルダー
- キラー、MAP、サバイバー画像の正式な使用範囲と権利確認
